# 上大师生身份：登录怎么做、验证码权力怎么拿

结论先说：**用学号/工号当账号是可行且应该做的**；**不要在我们的页面上收学校统一认证密码**；课设阶段验证码走 **学校邮箱**，短信和官方 SSO 是后两条路，要单独申请。

公开出处：

- 统一身份说明：[信息化工作办公室](https://its.shu.edu.cn/sytplb/xsfw/tysfrz.htm)
- 第三方系统接入申请：[系统统一身份认证申请](https://its.shu.edu.cn/sytplb/bmfw/xttysfrzsq.htm)
- 认证入口：[oauth.shu.edu.cn](https://oauth.shu.edu.cn/)
- 邮箱与二次验证：[信息办通知](https://newits.shu.edu.cn/info/1095/6192.htm)
- 信息服务电话：66133370、66133782（[服务电话](https://newits.shu.edu.cn/fwdh.htm)）
- 国内短信签名：[腾讯云签名审核标准](https://cloud.tencent.com/document/product/382/39022)

## 1. 三种“工号 + 密码/验证码”，只有一种现在就能做

| 方案 | 用户看到的 | 我们实际在验证什么 | 课设十周 | 风险 |
| --- | --- | --- | --- | --- |
| A. 页面上填学号/工号 + **学校统一认证密码** | 和选课系统一样 | 我们没有学校的密码库，只能把密码转交给学校，或自己存一份 | **不做** | 看起来像钓鱼；信息办不会认；一旦泄露就是安全事故 |
| B. 学号/工号 + **我们自己的密码**，首次用 **学校邮箱验证码** 证明是上大人 | 工号登录，验证码发到 `@shu.edu.cn` | 邮箱在学校域内，即视为本校师生 | **V1.0 采用** | 邮箱没激活的人要先去 `newsso.shu.edu.cn` 开通 |
| C. 跳转到学校 OAuth/SSO，回来带工号 | 点“上大统一身份登录”，在学校页面输密码和短信/企微二次验证 | 学校签发的身份 | **V1.1 / 加分，申请下来再接** | 要信息办批 client_id，十周不一定批得完 |
| D. 我们自己发 **手机短信验证码** | 工号 + 短信码 | 只能证明手机号，**不能单独证明是上大人** | 课设不做 | 个人主体基本发不了国内短信，见第 3 节 |

学校自己的验证码（登录邮箱、改手机号时收到的短信）是 **信息办的通道**，课设项目没有权限去调。师生在 `newsso.shu.edu.cn` / `oauth.shu.edu.cn` 上收到的码，和我们系统里的码不是一回事。

**分工：** 发码、校验、学号绑定、本平台密码全部归 **A**。E/F 只做登录页。详见 [六人分工](05-team-and-modules.md)。

## 2. V1.0 怎么登录（写入契约，第 5 周由 A 实现）

1. 用户填 **学号或工号**（`campusId`）和学校邮箱。
2. 点发送验证码：系统只向 **上大邮箱域** 发 6 位数字，5 分钟有效，同一学号 60 秒内只能发一次。
3. 邮箱域白名单：`shu.edu.cn`、`staff.shu.edu.cn`、`mail.shu.edu.cn`、`oa.shu.edu.cn`、`department.shu.edu.cn`（与信息办邮件通知里出现的域一致）。
4. 验证通过后设置 **本平台密码**（BCrypt）。之后日常用 `campusId + 本平台密码`。
5. 小程序仍保留微信 `code` 登录作为预览兜底，但必须绑定 `campusId` 才能报名、发布。
6. 管理员账号不走校园邮箱，仍用本平台密码 + 角色。

演示：组员用自己的上大邮箱走一遍；来不及开通邮箱时，后台可把指定 `campusId` 标成 `DEMO`，界面写明演示账号。

**明确禁止：** 输入框文案不得写成“统一认证密码”“一卡通密码”“E-Passport 密码”。帮助里写：“这是搭子平台自己的密码，不是选课系统的密码。”

## 3. 想发手机验证码，要拿什么权力

课设 **不依赖短信**。若以后要做，分两条，都不等于“调用学校短信网关”。

### 3.1 自己发（腾讯云 / 阿里云短信）

这不是学校批的权限，是运营商和云厂商的权限。

按腾讯云现行规则（[签名审核标准](https://cloud.tencent.com/document/product/382/39022)，2025-09-18 起个人不能再申请国内短信自用签名）：

1. 云账号做成 **企业认证**，或个人账号拿 **企事业单位授权委托书** 申请“他用”签名。
2. 提交签名归属方实名资质，运营商报备大约 **5–10 个工作日**。
3. 签名内容必须能对应主体，不能叫「验证码」「测试」。用「校园搭子」可以，用「上海大学」必须有学校授权，否则算冒用。
4. 再报验证码正文模板，例如：`您的注册验证码：{1}，请于{2}分钟内填写，如非本人操作，请忽略本短信。` 变量只能是 0–6 位数字。
5. 模板审核通过后才能调 API。费用按条计，课设阶段本来就打算 0–30 元，但 **没签名等于 0 条都发不出去**。

课设个人主体小程序走这条，大概率卡在签名。不要把答辩绑定在短信上。

### 3.2 用学校的短信（师生在统一认证里收到的那种）

那是学校 IdP 的二次验证，只有 **接入统一身份认证的应用** 才能间接受益：用户在学校页面完成短信/企微验证，我们只拿到授权码。我们 **申请不到“替学校发短信”的接口**。

要走这条，去做第 4 节的 SSO 申请，而不是去找短信网关。

## 4. 想用学校密码登录：向信息办申请 SSO

这是唯一正当的“工号 + 学校密码”做法：密码只打在 `oauth.shu.edu.cn`，我们拿 code 换身份。

建议本周就可以去问，不挡编码：

1. 打开 [系统统一身份认证申请](https://its.shu.edu.cn/sytplb/bmfw/xttysfrzsq.htm)，按部门服务流程准备材料。
2. 找课程负责老师或学院出具：这是软件工程课设、服务本校师生、不存储统一认证密码、不对接教务成绩。
3. 工作日打 **66133370 / 66133782**（宝山 D 楼 103，延长智能信息中心 101，嘉定综合楼 116），问：学生课设能否作为第三方应用接入、要哪些表、回调域名是否必须已备案 HTTPS。
4. 若批下来：得到 `client_id`、`redirect_uri`、允许的 scope。实现 `mode=SHU_OAUTH`：跳转学校登录 → 回调 → 绑定 `campusId` → 发我们的 JWT。
5. 若批不下来或要等到期末：V1.0 继续用方案 B，答辩说明“已申请、当前用邮箱域验证本校身份”。

未批准前禁止：模拟登录学校网站、截获 Cookie、把学校密码 POST 到我们服务器再去撞学校接口。

## 5. 和范围、风险的关系

- 身份验证是本校切口的一部分，不是把产品做成社交 App。
- 邮箱验证码用学校 SMTP 或第三方事务邮件均可；密钥进环境变量。
- 学号只存哈希或加密列对外接口不回传明文，见契约 UserBrief。
- 申请 SSO 的往来邮件不要提交公开仓库。
