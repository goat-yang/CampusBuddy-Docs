# 开发大纲与进度

更新：2026-10-15。六人、十周。编码尚未开始。阅读顺序：README → [过程与可行性](15-process-feasibility-risk.md) → 本文件 → [接口契约](04-api-contract.md) → 个人模块。开发是第 5 周才大规模开始的步骤。

## 1. 进度（与开发方案一致）

两次迭代 + 一次收尾。每周五例会。

| 阶段 | 周次 | 任务与产出 |
| --- | --- | --- |
| 需求与分析 | 第 1—2 周 | 功能清单与契约对齐；需求规格与用例；人员 GitHub |
| 设计 | 第 3—4 周 | 架构、E-R、接口落地到空工程、小程序与 Web 原型 |
| 迭代一 | 第 5—6 周 | M1—M4：可发布、可浏览、可报名（含满员与冲突） |
| 迭代二 | 第 7—8 周 | M5—M9：推荐、信用、通知、风控、评价、管理后台与看板 |
| 测试与验收 | 第 9 周 | 功能/接口/并发、推荐自测、缺陷修复、测试报告 |
| 部署与答辩 | 第 10 周 | 按 [部署说明](13-deployment.md) 发布网页；小程序开发者工具扫码或正式版；演示视频与代码量统计 |

V0.1：第 6 周末报名闭环。V0.5：第 8 周末亮点齐。V1.0：第 10 周末课程交付。

按人按周拆分与勾选标准见 [17](17-weekly-board.md)，不要另做一份私人进度表当真源。

## 2. 谁先交给谁

- A → E/F：登录 DTO（学号、邮箱验证码、本平台密码）、401；未绑学号报名 403。
- B → E/F：活动与报名 DTO；B → C：可曝光活动查询。
- C → E：推荐 list 与 reason、degraded。
- D → F：后台 API；D → 全组：Redis 与限流。
- F → 全组：Compose 端口；E → 全组：小程序 apiBase 与预览步骤。

## 3. 完成标准

P0：登录、发布、筛选、报名不超员、审核、敏感词。P1：推荐带理由可降级、信用流水、消息、看板。部署最低标准：网页能打开、小程序能在开发者工具扫码走通，且打到同一后端。
