# 智能推荐设计 v1.0

答辩亮点，也是最容易拖死进度的模块。先热度+标签，再加权，再 UserCF。Redis 挂了必须还能出列表。

## 1. 流水线

| 阶段 | 方法 | 规模 | 耗时预算 |
| --- | --- | --- | --- |
| 召回 | 兴趣标签、同类、地理范围、热门，取并集 | ≤300 | 20ms |
| 粗排 | 剔除已结束、已满员、已报名、拉黑、时间冲突 | ≤80 | 10ms |
| 精排 | 六因子加权 | 按分截断 | 15ms |
| 重排 | 打散、置顶、理由 | 10–20 | 5ms |
| 合计 | | | 推荐接口目标 P95 60ms，压测后再报 |

## 2. 公式

Score = 0.28 S_tag + 0.18 S_time + 0.15 S_geo + 0.13 S_credit + 0.12 S_hot + 0.14 S_cf

权重后台可改，保存时校验和为 1。各分项 [0,1]。S_geo：同楼栋 > 同校区 > 跨校区（跨校区默认 0，除非用户允许）。S_hot 用 Wilson 下界，避免 1 人报名的活动排第一。S_cf 无相似度表时该因子跳过并对其余权重归一化。

## 3. 工程

- 标签/热门召回走 Redis ZSet，禁止每次请求扫全表算余弦。
- 用户结果缓存 10 分钟，热门 5 分钟，空值短 TTL，TTL 加抖动。
- 特征 30 分钟离线刷新 `t_user_feature`。
- 埋点：曝光/点击/报名/忽略/不喜欢。负反馈：同类多次曝光不点击则该类权重衰减，幅度 10% 仅作用于该用户缓存，不改全局配置。
- 冷启动：问卷标签 + 同学院热门 + 20% 探索位；新活动进扶持池。
- 理由取贡献最高的两个因子生成固定模板句，不调用 LLM。
- 三级降级：跳过坏因子 → 分类热门 → DB 热度视图。响应 `degraded`。

## 4. 验收话术

强调缓存、降级、埋点、可调权重，不强调“深度学习”。转化率 1.2 倍是目标，内测样本 <100 时只展示对比表并标明样本，不宣称算法有效。
